# FoyerLauncher

`app/` is the shared UI for both platforms. `app/device.js` is the Samsung Tizen adapter; `app/device-android.js` is the Android TV / Google TV adapter, used inside the `android/` shell (bridge `window.FoyerAndroid`) or in the browser preview with `?device=android`. Read `docs/development.md` and `docs/interaction-behaviour.md` before app changes. For a new contributor or a separate TV installation, also read `docs/for-agents.md`; to install on someone's TV, follow `docs/agent-android-setup-guide.md` (Android TV / Google TV) or `docs/agent-tv-setup-guide.md` (Samsung). Ask the owner for the TV's details and IP address; never write them into tracked files.

Use simple HTML, CSS and ES5-compatible JavaScript for the TV. Node tooling can use modern JavaScript. Preserve remote focus/navigation, preference migrations and cached rendering. Keep device details in the adapters. Read `docs/assets.md` before changing images, glass geometry or icon sizing; keep live blur and pixel analysis off the TV animation path.

Run `npm run check` for app changes. For interaction changes, run the browser preview and `FOYER_PUBLIC_FONTS=1 npm run check:browser`; public contributors must not need proprietary fonts. Run `npm run check:android` when changing `app/device-android.js`, the `android/` shell or anything the Android adapter relies on. Run `npm run check:debloat` when changing `debloat/` or `android/*.sh`. Run `npm run check:public` and `npm run export:public` before preparing a public download. Follow `CONTRIBUTING.md` and retain third-party notices.

Browser/repository tasks do not authorise device access. This covers both platforms: Tizen installs, launches and native helper queries, and Android adb installs, `android/install.sh`, `android/restore.sh`, `scripts/marks-from-tv.mjs` and any TV settings change. Each needs an explicit device task. Read `docs/tv-status.md` before Samsung compatibility claims and `docs/agent-tv-setup-guide.md` before a new Samsung setup. Announce any installation, app launch or restart; confirm visible results with the TV's owner. Treat Samsung native Home/startup writes as a separate task with explicit authority and an exact-value recovery baseline.

Keep an existing installation's package/application identity and signing key stable so updates install in place. For an independent Samsung installation, generate its own identity and certificates, and update manifest checks, launch/self-filter IDs and helper targets consistently. `scripts/package.py`, `scripts/tv.py` and `scripts/native-home/` contain reference-machine assumptions; they are not an unattended installer.

Setting up someone's TV follows `docs/agent-android-setup-guide.md` (Android TV, Google TV, Fire TV, any brand) or `docs/agent-tv-setup-guide.md` (Samsung). Ask the owner for the TV's brand, model, platform, OS version and IP address; show them the debloat list and hide only what they choose; make matching app logos with `scripts/marks-from-tv.mjs --auto` and let them review the preview; never hide anything a list marks keep or never, and never edit the lists to get past a refusal; finish by showing them the restore script in `my-tvs/<model>-<serial>/`.

Keep proprietary fonts, signing keys, passwords, device identifiers, addresses, SDKs, recovery values and generated packages in ignored `.local/`, `android/.local/` or `dist/`. Each TV's records and restore script stay in ignored `my-tvs/`. Marks made from a TV's own apps stay in ignored `app/assets/icons/local/`. Never commit paid font binaries or signing keys, or publish a private-font build. Public-code licensing does not replace the terms in `THIRD_PARTY_NOTICES.md`.

Use the contributor's own authenticated GitHub account for GitHub CLI work. Preserve shared or uncommitted work. Use reversible deletion; never reset, force-push or rewrite history without explicit authority. Publication/visibility changes require a separate instruction.
